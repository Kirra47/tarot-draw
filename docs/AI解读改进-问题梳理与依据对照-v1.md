# AI 解读改进：问题梳理与依据对照 v1

日期：2026-09-28。状态：本地改进与抽样验收完成；未提交、未部署。真实模型抽样仅用于找提示词边界，不构成质量统计或稳定性保证。

## 结论

先修正资料、提示词和会话上下文的不一致，再引入《需求.pdf》的问题梳理方法。仅增加一套“深层问题分析”提示词，可能把现有错误解释得更像真的。

产品需要保留亲手摇六次的参与感，减少无效阅读；“操作更少”不是所有环节的共同目标。结果应让人看清：本次得到什么、解释引用哪里、与自己问的事有什么关系、哪些仍然不知道。

## 二、上一轮方案还需要修正的四点

### 1. 问题梳理不能替用户改题

PDF 的“区分表象与问题、检查假设和边界”值得借用；“隐性利益、根结构、真实损失”只能作为待核对的假设，不能自动生成事实。

保留用户原问题的对象、选项、时间范围和目的。只有歧义会实质影响答案时，才简短指出，并最多问一个关键问题；不新增必填问卷，也不另开一次分析请求。

例：“我到底周六还是周天去上班？”不能改写成“你真正纠结的是工作与自由”。先区分是在问已安排的班次，还是自行选择哪天；排班事实不能靠卦象查证。没有依据把某个符号对应到某一天时，不随意选一天。

### 2. 专业性需要一条看得见的解释联系

短解应在资料足够时包含至少一处具体联系：本次牌位/卦/爻的某个信息 → 采用的象征含义 → 为什么与原问题有关。术语可以保留，但要就地解释；不要求逐项翻译整套资料。

分别标明：程序记录的结果、原典及出处、本站现代说明、AI 针对问题的解释、用户提供的现实条件。原典能支持“这句古文从哪里来”，不能证明“对方确实欺骗了你”或“某日一定发生什么”。

同样，“初爻=起步、三爻=转折”这类本站通用提示，不能冒充针对本卦爻辞的专门分析。无动爻时不得为了满足模板硬找动爻。

### 3. 固定的“两点＋一个行动”仍可能制造模板味

把它作为长度上限，不作为必填栏位。解释卦义可以止于解释；选择题应讨论区分条件；射覆是候选线索；空问题只做一般解读，不虚构人生背景。

二合一允许牌与卦提供不同侧重点。不能每次都归纳成“稳中求进”，也不因为两套象征表述相似就声称预测更可信。若确有分歧，指出分歧和适用条件即可。

### 4. 固定本次牌卦，不代表固定首次判断

用户补充现实信息后，允许修正旧解释并简短说明原因。新事实应能使某个解释不成立，不能任何反馈都被包装成“早已被卦象预示”。

用户说“详解第二点什么意思”，模型必须读得到那一段；用户纠正后再点详解，也不能退回首次短解的错误前提。上下文预算不足时优先保留明确更正与当前被追问内容，而非机械只截最后几条。

## 三、精简提示词草案

这是拟替换/合并现有重复规则的草案，不应继续叠加在冲突的旧提示词之上。保留现有安全约束；方法允许的字段由程序决定。

```text
根据本次实际资料回应用户的原问题，用简洁自然的中文。

1. 忠实保留问题的对象、选项、时间范围和目的。不要替用户发明
   “真正的问题”、隐秘动机、第三方想法或经历。必要时指出一个关键歧义。
2. 使用当前模式与起卦方法实际提供的资料。缺少的牌、互卦、体用、
   动爻或原文均不补造；引用经文只能使用材料包中的原文及来源。
3. 资料足够时，选择一至两处与问题相关的具体信号，简短解释
   “这里是什么含义、为何与这个问题有关”。不复述全部资料。
   无法建立合理联系时直接说明，不强行套用。
4. 区分原典、现代释义、AI 的象征性解释和用户现实事实。
   象征性解释不构成事实证明，也不保证预测结果。
5. 直接回应，但不强行下结论。通常 120—180 字，约 220 字以内；
   不为凑结构添加泛泛建议。解释性问题不必附行动建议。
6. 二合一允许不同侧重点和分歧；不强行把牌卦说成相互验证。
7. 沿用本次固定结果。用户明确更正优先于先前 AI 的猜测；
   需要修正时说明因何修正，不重抽、不重起、不维护错误前提。
```

详解沿用这些约束，按实际方法展开相关材料；追问优先回答最新问题，不重写整篇报告。此草案仅定义可观察的回答要求，不要求展示隐藏推理过程。

## 四、实施顺序与边界

1. **修输入一致性。** 按 `readingMode` 和 `castMethod/ruleProfile` 明确允许的数据，消除铜钱/梅花冲突与错误问题落点；用纯本地测试覆盖。本站三钱法与梅花的区别以当前项目规则为准，不宣称覆盖所有传统流派。
2. **统一一次解读的资料与会话。** 固定结果单独保存；来源材料含标识、原文、出处、现代说明；用户更正与已展示回答可追踪。设置长度预算和截断标记，避免关键更正、来源文字被无声截断。资料与对话仍是待分析数据，不是系统指令。
3. **再替换短解规则。** 在原有一次请求中完成有限的问题澄清和依据说明，不增加新菜单、必填步骤或额外“根因分析”调用。
4. **用固定样本比较新旧输出。** 先完成本地结构验收，再小规模调用真实模型评阅；模型版本、规则版本和固定牌卦记录一致，避免换模型或重起卦混淆比较。
5. **线上接入另行验收。** 本轮修改只落在本地工作树，没有提交或部署；线上版本的一致性尚未检查，也不能把本地结果误写成线上验收通过。

暂不做完整六爻断法引擎、多 Agent 自动辩论、向量知识库、自动反馈学习或新一轮视觉重做。当前问题不需要这些扩展才能解决。

## 五、首轮验收样本

验收样本使用固定记录，起卦结构须由项目真实计算函数生成，不得手写不一致的卦名与爻值。下表是持续回归清单；项目方案、排班和关系三类已做合成输入的真实模型抽样，其余样本尚未逐项完成。

| 编号 | 输入/操作 | 重点验收 |
| --- | --- | --- |
| 01 | 铜钱法，无动爻 | 不编造动爻，不输出本站该方法不使用的互卦/体用。 |
| 02 | 铜钱法，多动爻（覆盖六动爻） | 保留实际数量与内容，不压成单动爻，不默选某个未实现的断法。 |
| 03 | 梅花法，固定本/互/变及体用 | 只用实际结果；相关解释能指出具体资料，而非套铜钱规则。 |
| 04 | “这个项目还有其他方案吗？” | 不因“其他”的“他”转向关系/读心。 |
| 05 | “他欠我的钱还能拿回来吗？” | 不因代词忽略欠款问题；不编造对方动机或把象征当追回保证。 |
| 06 | “我到底周六还是周天去上班？” | 保留两个选项，区分排班事实与自主选择，不编造日期对应。 |
| 07 | 同一牌卦，分别问具体选择与某句卦辞含义 | 回答类型跟随任务，不给每题同一套行动建议。 |
| 08 | 同一个问题，替换成含义明显不同的合法牌卦记录 | 引用与解释随实际材料合理变化；不要求现实建议必须相反。 |
| 09 | 补充一条与旧解释前提冲突的现实事实，再开详解 | 新事实被保留；必要时承认并修正旧解释，牌卦不变。 |
| 10 | 看完详解后追问“第二点是什么意思？” | 能指向用户看到的实际段落，不猜内容。 |
| 11 | 二合一，两组材料有不同侧重点 | 保留差异并说明适用条件，不强行同意、不把一致当准确性证明。 |
| 12 | 空问题、原典缺失、单塔罗模式各一例 | 不虚构背景/经文；未选功能不出现，也不输出“不适用”占位章节。 |

判退项：错方法或改结果、补造原文/出处、编造现实事实、擅改原问题、忽略用户明确更正。出现任一项，该样本退回修订。

质量评阅：是否贴题；具体依据是否正确且解释联系成立；不确定性是否准确；是否易读；是否有冗余。每项人工记 0/1/2 分并写一句理由，供新旧对照，不当作统计可靠性证明。

补做“删去牌卦”检查：如果整篇仍可原样回复任意问题，应检查是否只有通用建议。合理的现实建议可能在换卦后保持不变，不能为了显得有区别而强改建议。真实模型少量样本不能证明稳定，边界样本还需重复验证。
