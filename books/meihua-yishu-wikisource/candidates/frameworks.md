# 梅花易数候选框架：可执行方法单元

> 阶段 1 原始候选池。以下内容把《梅花易数》中的“法”重写为可审计的输入—步骤—输出流程，不把古代占例当作现代预测证据。所有计算结果必须保存起卦模式、原始输入、版本和出处；阶段 1.5 再做版本校勘与交叉验证。

## F1. 先天时间／数起卦

**触发场景**：用户有明确问题，选择“按起卦时间”或“按数字起卦”；抽牌完成后也可将抽牌时刻作为一次可复现的起卦时间。

**输入**：

- 起卦时间：年、月、日、时，以及时区；
- 年月日时对应的传统序数：年支子至亥为 1–12，月份正月至十二月为 1–12，日为 1–30，时支子至亥为 1–12；
- 可选的额外数字；
- 采用的“先天数”版本。

**步骤**：

1. 按所选版本把时间字段转换为四个传统序数，并保存转换过程；不要把公历月份、农历月份或时区静默混用。
2. `年月日总数 ÷ 8`，余数对应上卦；余 0 按 8 处理，按乾 1、兑 2、离 3、震 4、巽 5、坎 6、艮 7、坤 8 映射。
3. `年月日时总数 ÷ 8`，余数对应下卦；同样把余 0 按 8 处理。
4. `年月日时总数 ÷ 6`，余数为动爻；余 0 按第六爻处理。动爻阴阳翻转，得到变卦。
5. 记录本卦、动爻、互卦、变卦和输入快照，供同一问题复算。

**输出**：一个带公式的 `MeihuaCast`：`methodMode=先天`、时间与时区、上下卦、动爻、本／互／变卦、计算过程和出处链接。

**原文来源**：[卷一“周易卦数”“卦以八除”“爻以六除”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%80)、[卷一“年月日时起例”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%80)。

**边界**：这是传统编码规则，不是随机抽样或已验证的预测模型。历法、日界、时区和闰月换算必须显式显示；若换算不确定，停止起卦并提示用户确认。不能把先天模式生成的结果静默套入后天模式。

## F2. 后天物象／声音／文字起卦

**触发场景**：用户主动选择“现场取象”，并明确提供一个可数的物件、声音、文字或人物／物体象；不因摄像头画面自动抓取征象。

**输入**：

- 取象类型：物数、声音、文字、人物、动物、静物或方位；
- 用户实际观察到的数量、字符数、声音次数、对象类型、方位和发生时间；
- 时间对应的时支数；
- 用户问题。

**步骤**：

1. **物数**：物件数量作上卦，时数作下卦；物数与时数合计除六取动爻。
2. **声音**：声音次数作上卦，时数作下卦；声音数与时数合计除六取动爻。
3. **文字**：一至十一字按原书的分配规则取上下卦；十一字以上按字数分半，奇数时少字为上卦、多字为下卦；再以总数除六取动爻。四字以上的声调取法只有在用户明确选择该版本时启用。
4. **人物或外物**：依原书的八卦类象、服色、身体动作、手持之物或所处方位先确定一个卦，再用方位作另一卦，并加时数取动爻。
5. 生成本／互／变卦后，保存“事实观察”和“卦类映射”两个字段，禁止把模型联想写成事实。

**输出**：`methodMode=后天` 的起卦记录、事实观察清单、映射依据、卦象结构和可复核计算式。

**原文来源**：[卷一“物数占例”“声音占例”“字占”“一字占至十一字占”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%80)、[卷一“为人占”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%80)、[卷一“物卦起例（端法后天起卦）”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%80)。

**边界**：静物不是“随便看到就能占”；原书对屋宅、树木、器物等有起创／置成条件。现场模式必须由用户确认并可撤回，不保存未经同意的摄像头、声音或他人信息。不要让语言模型自动扩展一物多象。

## F3. 动爻—互卦—变卦结构解析

**触发场景**：任一模式已经得到本卦和动爻，需要把结果拆成“当前—中段—后段”的结构。

**输入**：六爻序列、本卦、动爻、起卦模式、问题文本。

**步骤**：

1. 按动爻位置翻转阴阳，生成变卦；保留爻位从初爻到上爻的编号。
2. 去掉本卦初爻和上爻，将中间四爻分成上下两个三爻卦，生成互卦；乾、坤无互时按所选版本记录特殊处理。
3. 有动爻时把动卦作为“用”、静卦作为“体”；无动爻时记录为“本卦无动”，不要擅自补动爻。
4. 给四个结构分配解释角色：本卦是当前框架，用卦偏即时，互卦偏中段，变卦偏后段；体互与用互按体所在上下卦区分。
5. 后天模式先查相关爻辞兼卦辞；先天模式先以卦象论，是否显示爻辞由版本开关决定。

**输出**：结构时间线、动爻说明、本／体／用／互／变卦图、原文索引和“当前—中段—后段”三段解释槽位。

**原文来源**：[卷一“爻以六除”“互卦起例”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%80)、[卷二“占卜总决”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)、[卷三“体用互变之诀”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%89)。

**边界**：多动爻、特殊互卦和不同传本的取体方式必须做成版本选项；不能把一本书中的示例硬编码成所有流派的唯一算法。这里的“中段／后段”是传统解释位置，不是现实时间保证。

## F4. 体用—五行—卦气旺衰分析

**触发场景**：本／体／用／互／变结构已经生成，用户希望看到关系而不是只看一句吉凶。

**输入**：体卦、用卦、互卦、变卦、起卦时令／月份、问题类型。

**步骤**：

1. 映射五行：乾兑金、坤艮土、震巽木、坎水、离火。
2. 对体与用、互、变分别计算“生、克、比和、体生用、用生体”等关系；把每一项保留为证据，不立即合并成单一分数。
3. 根据季节判断卦气旺衰：春木、夏火、秋金、冬水，辰戌丑未月土旺；记录生体之气是否旺、克体之气是否衰。
4. 依用—互—变的优先顺序汇总：用是即时信号，互是中段，变是末段；体盛受生与体衰受克分别标记为支持／阻力。
5. 输出“支持、阻力、待核实”三栏，并用原文证据解释，而不是直接输出宿命式结论。

**输出**：五行关系矩阵、旺衰状态、阶段性证据、冲突项和结构化解释提示。

**原文来源**：[卷一“五行生克”“八宫所属五行”“卦气旺／衰”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%80)、[卷二“体用总诀”“衰旺论”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)、[卷二“人事占第二”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%89)。

**边界**：旺衰算法依赖月令、历法和流派；不得与八字、紫微或其他术数的五行权重静默混合。疾病、财务、法律等问题只显示传统文本的文化说明和现实核查项，不给诊断、投资或法律结论。

## F5. 问题类型适配器：从结构到条件式建议

**触发场景**：用户在起卦时选择“人事、家宅、求谋、求名、求财、交易、出行”等问题类型。

**输入**：问题类型、问题原文、F3 结构、F4 关系矩阵、用户可核实的现实背景。

**步骤**：

1. 先执行通用顺序：爻辞／卦辞 → 体用 → 互变 → 旺衰 → 克应；把《易》文本和传统类象分开显示。
2. 按问题类型替换“体”和“用”的语义：例如人事以体为主、用为宾；家宅以体为人、用为家宅；求财以体为求问者、用为财；交易以体为主、用为财与交易对象。
3. 用生克关系写成条件句：如“若用生体，传统文本倾向解释为有助力；现实上可核查的助力是……”，不得把条件句压成必然事件。
4. 输出至少一个现实核查问题、一个可逆行动和一个不确定性说明。
5. 对健康、官讼、重大财务等类型自动降级为“文化解读＋求助专业人士”模式。

**输出**：领域化证据卡、原文出处、现实核查清单、下一步行动和安全提示。

**原文来源**：[卷二“占卜总决”“占卜论理诀”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)、[卷二“体用生克篇之二”各事类占](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)。

**边界**：这些是古代事类的解释模板，不是现代决策规则；不得把婚姻、疾病、官讼、求财的古代吉凶语句原样当成建议。问题背景不足时输出“无法判断”，而不是补写背景。

## F6. 三要／十应现场证据记录

**触发场景**：用户主动开启“记录当下环境”，希望把起卦时的可见、可听和可感线索作为辅助材料。

**输入**：起卦时刻、地点／方位、天时、人物、人事、时令、动物、静物、言语、声音、颜色、文字，以及每项“向我而来／离我而去”的方向性。

**步骤**：

1. 在解读前记录事实：发生了什么、何时、来自哪个方向、用户是否确认；不得先看卦再挑选符合故事的征象。
2. 将事实标为三要（耳、目、心的观察）和十应类别；映射到卦象时保存映射理由。
3. 以体用为“内”，三要／十应为“外”，比较内外是否一致；内外一吉一凶时输出“混合证据”，不强行裁决。
4. 记录向背：生体之应来临可作将至，离去可作已过；克体之应同理，但只作为传统时间线索。
5. 若用户在安静环境中没有外部征象，使用静占模式，只分析本／体／用和时令，不虚构外卦。

**输出**：现场证据日志、类别与方向、内外一致性、冲突说明和是否采用静占的标志。

**原文来源**：[卷二“三要灵应篇”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)、[卷二“十应奥论”“十应目论”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)、[卷二“内外论”“向背”“静占”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)。

**边界**：克应是辅助证据，不是第二次抽卡；不能用摄像头或麦克风自动监视、识别他人。所有现场内容必须由用户主动确认，可删除，并在解释中标明“传统类比”而非事实因果。

## F7. 克应／应期的范围估计

**触发场景**：用户明确询问“何时发生、多久见效、什么时候回音”，并同意查看传统应期推法。

**输入**：全卦数、体用互变关系、时令、问题的持续时间类别、器物／事件的耐久性、起卦时的动静状态。

**步骤**：

1. 先判断问题的时间尺度：当日、近期、月度或长期；日、月、年单位必须由问题和对象决定，不能无条件套用。
2. 对吉事寻找生体或比和的卦气，对阻力寻找克体的卦气；将对应的天干、地支、季节或卦数记录为“传统候选时段”。
3. 结合结构位置：用卦偏近，互卦居中，变卦偏后；器物类再按草木／金石等耐久性选择日、月或年尺度。
4. 结合动静修正速度：坐／卧偏慢，行偏快，走更快；只形成“较快／较慢”的解释，不生成精确倒计时。
5. 输出候选时间范围、依据、反证条件和用户可以观察的事件指标；没有生体或比和证据时明确标注“不足以估计”。

**输出**：`timingEstimate`（尺度、候选区间、依据、置信限制）、可核查指标和复盘日期。

**原文来源**：[卷二“先天后天论”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)、[卷三“占卜克应之诀”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%B8%89)、[卷二“动静”](https://zh.wikisource.org/zh-hans/%E6%A2%85%E8%8A%B1%E6%98%93%E6%95%B8/%E5%8D%B7%E4%BA%8C)。

**边界**：应期是古代经验性解释，不能用于安全期限、医疗延误、法律时限或投资择时。输出区间而非保证日期；如果用户把结果用于高风险决定，应停止占断并给出现实信息来源和专业求助建议。

## 阶段 1 选择建议

首批实现优先级建议为 **F1 → F3 → F4 → F5**。F2 和 F6 涉及现场输入与隐私，作为用户主动开启的可选模式；F7 仅在明确询问时间时显示。所有框架都应在界面上显示“起卦方式、流派版本、原文出处、传统文化／自我反思用途”的信息。
